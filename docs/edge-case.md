# RupeeRadar — Edge Cases & Corner Scenarios Specification

This document details all known and potential edge cases, corner scenarios, and anomaly modes across the **RupeeRadar** architecture and implementation pipeline. It serves as the engineering reference for robust parser design, data sanitization, financial accuracy, defensive heuristics, and comprehensive test suite fixtures.

---

## 1. Edge Case Classification & Severity Matrix

Edge cases are classified by architectural impact and user financial trust risk:

| Severity | Definition | Impact on User / System | Example |
|---|---|---|---|
| **P0 (Critical)** | Pipeline crash, data corruption, privacy leak, or complete failure to process statement | User blocked, data lost, or PII exposed | Division by zero in metrics; unhandled encoding crash; PII leaked to LLM |
| **P1 (High)** | Inaccurate financial metrics, massive miscategorization, or double-counting | Skewed financial picture; user loses trust in numbers | Self-transfers counted as income; double counting credit card bill payments |
| **P2 (Medium)** | Heuristic inaccuracy, suboptimal UI rendering, or degraded fallback mode | Partial insight degradation, fallback to "Other", layout overflow | Variable utility bills missed as recurring; very long merchant string wraps table |
| **P3 (Low)** | Minor cosmetic or presentation issue with negligible calculation impact | Visual imperfection or minor rounding difference | Trailing decimals in rounding (₹0.01); non-standard date format warning logged |

## 2. Ingestion & File Parsing Edge Cases (Pipeline Stage 1)

### 2.1 File Encoding and BOM Handling
- **Scenario:** Bank statement CSV exports generated by core banking systems (e.g., Finacle, BaNCS) often export in non-UTF-8 encodings such as `UTF-8 with BOM` (`\xef\xbb\xbf`), `Windows-1252` (`cp1252`), `ISO-8859-1` (`latin1`), or `MacRoman`.
- **Failure Mode:** `UnicodeDecodeError` in Python during file read, crashing `POST /upload`.
- **Handling Strategy:**
  - In `backend/app/parsers/generic_csv.py`, read files using `charset-normalizer` or multi-encoding fallback (`utf-8-sig` -> `utf-8` -> `cp1252` -> `latin-1`).
  - Strip byte-order marks (`\ufeff`) prior to header inspection.

### 2.2 Bank Statement Header & Metadata Preamble
- **Scenario:** HDFC, SBI, and ICICI bank statements typically contain 5 to 25 lines of account metadata before the actual transaction table headers:
  ```text
  HDFC BANK LIMITED
  Account Branch: KORAMANGALA 4TH BLOCK
  Account No: 501000******89
  Customer Name: JOHN DOE
  Statement Period: 01-Jan-2025 to 30-Jun-2025
  ...
  Date,Narration,Chq/Ref No,Value Dt,Withdrawal Amt,Deposit Amt,Closing Balance
  ```
- **Failure Mode:** Standard `pandas.read_csv()` assumes row 0 is the table header, failing with incorrect column names or parsing header lines as corrupted data rows.
- **Handling Strategy:**
  - Dynamic header detection: scan the first 30 rows looking for anchor keywords (`date`, `narration`, `description`, `withdrawal`, `debit`, `deposit`, `credit`, `balance`).
  - Set `skiprows` dynamically in `pandas.read_csv()` once the header row index is identified.

### 2.3 Trailing Disclaimers, Account Summaries & Empty Rows
- **Scenario:** Statements frequently terminate with multi-line footers:
  ```text
  Total Debits: 87,500.00 | Total Credits: 1,25,000.00
  ** END OF STATEMENT -- Generated on 01-07-2025 **
  Note: Cheques deposited are subject to realization.
  ```
- **Failure Mode:** Trailing summary rows contain numbers that get parsed as regular transactions, severely inflating spend or income metrics.
- **Handling Strategy:**
  - Validate that the row contains a valid parseable date in the date column; discard rows failing date validation.
  - Reject rows containing summary keywords (`Total`, `Closing Balance`, `End of Statement`, `Generated on`).
  - Drop all rows where both debit and credit (or amount) are null/NaN.

### 2.4 Multiline & Wrapped Narrations
- **Scenario:** In certain bank CSVs, long transaction narrations are wrapped across two physical lines enclosed in unescaped or broken quotes.
- **Failure Mode:** CSV parser treats line 2 as a new row with missing columns, causing row alignment failure (`ParserError: Expected N fields, saw M`).
- **Handling Strategy:**
  - Use Python standard library `csv.Sniffer` and `csv.reader` with robust quoting options (`csv.QUOTE_MINIMAL`, `quoting=csv.QUOTE_NONNUMERIC`).
  - Log parse warnings for malformed rows and skip unrecoverable lines without failing the entire file.

### 2.5 Column Shape Variations (Dual-Column vs. Single-Column Amounts)
- **Scenario:**
  - *Format A (HDFC/ICICI/SBI)*: Separate columns for `Withdrawal Amt (Dr)` and `Deposit Amt (Cr)`.
  - *Format B (Fintech / UPI apps)*: Single `Amount` column with a separate `Transaction Type` (`DR`/`CR` or `DEBIT`/`CREDIT`).
  - *Format C (Standard accounting)*: Single signed `Amount` column (+ for credit, − for debit).
- **Failure Mode:** Assigning credits as debits or vice-versa, causing inverted savings and cash flow calculations.
- **Handling Strategy:**
  - Canonical transformation in `StatementParser`:
    - If separate debit/credit columns: `amount = -abs(debit)` if debit > 0 else `+abs(credit)`.
    - If single column + type: normalize type (`DR`, `DEBIT` -> `-abs(amount)`, `CR`, `CREDIT` -> `+abs(amount)`).
    - If trailing DR/CR indicator (e.g. `500.00 Dr`): parse regex `([0-9.,]+)\s*(Dr|Cr)?`.

### 2.6 Indian Currency Number Formatting
- **Scenario:** Values formatted with Indian numbering system groupings and symbols:
  - `₹ 1,25,000.50` or `Rs. 1,25,000.50`
  - Comma placement: `1,00,000.00` (lakh) vs international `100,000.00`.
  - Enclosed in parentheses for negative numbers: `(1,500.00)`.
  - Spaces or non-breaking spaces (`\xa0`) inside amount strings.
- **Failure Mode:** `ValueError: could not convert string to float`.
- **Handling Strategy:**
  - Normalization utility regex: `clean_amount_str = re.sub(r"[^\d.-]", "", val)`.
  - Check for parentheses `(val)` indicating negative debit before stripping.

### 2.7 Date Ambiguity and Mixed Formats
- **Scenario:** Statements containing dates like `03/04/2025` (is it 3rd April or 4th March?) or mixed formats within the same file (e.g. `05-OCT-2025` vs `05/10/2025`).
- **Failure Mode:** Misordering of transactions, false intervals in recurring payment detection, incorrect monthly groupings.
- **Handling Strategy:**
  - In Indian banking contexts, standard format preference is `DD/MM/YYYY` or `DD-MM-YYYY`.
  - Implement heuristic date inspection across the whole file: if any row has day > 12 in the first token (e.g., `25/04/2025`), infer `dayfirst=True` for the entire dataset.
  - Support `DD-MMM-YYYY` (e.g., `05-JAN-2025`) using `dateutil.parser`.
  - Store dates strictly as ISO 8601 (`YYYY-MM-DD`).

### 2.8 Edge File Conditions
- **Scenarios:**
  - 0-byte file uploaded.
  - File with headers only (0 transaction rows).
  - Huge file exceeding 10 MB limit (e.g., 5-year corporate statement).
  - Password-protected Excel or PDF files.
  - Corrupt or non-tabular binary files uploaded with `.csv` extension.
- **Handling Strategy:**
  - Enforce `10 MB` hard size limit in FastAPI middleware; return `413 Payload Too Large`.
  - If 0 transaction rows parsed: return `422 Unprocessable Entity` with user message: *"No transactions found in this file. Please verify statement dates and format."*
  - If password protected: return `422 Unprocessable Entity` with message: *"Password-protected statements are not supported for privacy and security reasons. Please upload an unlocked CSV."*

## 3. Cleaning & Normalization Edge Cases (Pipeline Stage 2)

### 3.1 Complex Indian UPI Narration Formats
- **Scenario:** Variations across banks and apps (Google Pay, PhonePe, Paytm, BHIM):
  - `UPI/DR/412345678901/SWIGGY/HDFC/pay-to-swiggy/UPI`
  - `UPI/CR/512345678902/KUMAR R/ICIC/Refund/UPI`
  - `UPI-412345678903-ZOMATO LIMITED-HDFC-9876543210@paytm-ORDER123`
  - `UPI/P2P/1234567890/RAMESH/PAYTM` (Person to person transfer)
  - `UPI/P2M/9876543210/ZEPTO/YESB` (Person to merchant)
- **Failure Mode:** The entire raw string remains uncleaned; merchant is obscured by reference numbers, bank codes, or VPA handles.
- **Handling Strategy:**
  - Regex cleaning pipeline in `backend/app/pipeline/cleaner.py`:
    1. Strip standard UPI prefix tokens (`UPI/DR/`, `UPI/CR/`, `UPI-`, `UPI/P2P/`, `UPI/P2M/`).
    2. Extract numeric 12-digit RRN / UTR reference numbers and place into `metadata.upi_ref`.
    3. Remove trailing VPA strings (e.g. `@okhdfcbank`, `@paytm`, `@ybl`).
    4. Isolate the target merchant name and match against known merchant dictionary.

### 3.2 POS, E-Commerce, and Card Swipe Narrations
- **Scenario:**
  - `POS 412345XXXXXX1234 RELIANCE RETAIL MUMBAI IN`
  - `ECOM PUR/AMAZON SELLER SER/01-06-25/14:22`
  - `VISA DCR 4591XXXXXXXX1234 FLIPKART PAYMENTS`
- **Failure Mode:** Masked card numbers and terminal locations prevent direct string matching.
- **Handling Strategy:**
  - Strip card masking patterns: `r"\b\d{4,6}[X*]+\d{4}\b"`.
  - Strip POS/ECOM tags: `r"^(POS|ECOM PUR|VISA DCR|INB|BIL|NEFT|RTGS|IMPS)\s*"`
  - Set `payment_mode = "card"` or `"pos"`.

### 3.3 Truncated Merchant Names
- **Scenario:** Bank statement columns with 20–30 character truncation limits:
  - `NETFLIX ENTERTAINME` (Netflix)
  - `AMAZON PAY INDIA P` (Amazon)
  - `IRCTC WEB TICKETING` (IRCTC)
  - `SWIGGY INSTAMART B` (Swiggy)
- **Handling Strategy:**
  - Fuzzy matching (Levenshtein ratio > 0.85) and prefix matching against `merchant_dict.py`.
  - Token-level matching: `token_set_ratio` matches `"NETFLIX"` within `"NETFLIX ENTERTAINME"`.

### 3.4 Reversals, Failed Transactions & Immediate Refunds
- **Scenario:**
  - Debit: `2025-06-01 | UPI/SWIGGY | -₹450.00`
  - Immediate reversal: `2025-06-01 | REV-UPI/SWIGGY/REFUND | +₹450.00`
  - Or a failed ATM withdrawal reversed 5 minutes later.
- **Failure Mode:** Both the debit and the reversal are counted, inflating both Total Spend and Total Income by ₹450 without net spend change.
- **Handling Strategy:**
  - Detect reversal keywords (`REV-`, `REVERSAL`, `REFUND`, `FAILED TXN`).
  - Flag matched debit/credit pairs with identical absolute amounts and merchant within a 48-hour window as `metadata.is_reversal = True`.
  - Exclude paired reversals from Top Categories and Spend metrics.

### 3.5 Zero-Amount Transactions and Token Verification Debits
- **Scenario:** ₹0.00, ₹1.00, or ₹2.00 micro-debits used for UPI mandate setup (Netflix, Autopay) or credit card tokenization, often immediately refunded.
- **Failure Mode:** Skews average transaction metrics and clutters biggest transactions/insights.
- **Handling Strategy:**
  - Exclude ₹0.00 transactions from category totals.
  - Tag ₹1.00 - ₹2.00 mandate verifications with category `Other` or flag in metadata.

## 4. Categorization Edge Cases (Pipeline Stage 3)

### 4.1 Multi-Category Merchants
- **Scenario:** A merchant offers multiple unrelated services:
  - `Amazon`: Shopping (electronics, clothes) vs Food (Amazon Fresh) vs Subscriptions (Prime) vs Bills (Amazon Pay).
  - `Tata Neu`: Shopping vs Grocery (BigBasket) vs Travel (Air India).
  - `Paytm`: Wallet top-up vs Electricity bill vs Cinema tickets.
- **Handling Strategy:**
  - Keyword refinement: If description contains `PRIME` or `RECHARGE` or `FRESH`, categorize specifically (`Subscriptions`, `Bills`, `Food`).
  - Otherwise, assign to primary category (`Amazon` -> `Shopping`) with moderate confidence (0.80) rather than 1.0.
  - Allow seamless user inline category override in UI.

### 4.2 Non-Income Credit Transactions
- **Scenario:**
  - Credit from a friend via UPI (`UPI/CR/123/ANIL SHARMA` for ₹1,200 split bill).
  - Refund for returned e-commerce product (`AMAZON REFUND` +₹3,500).
  - Bank interest credit (`INT.PD 01-01-2025 TO 31-03-2025` +₹240).
  - Credit card cashback (`CASHBACK RECEIVED` +₹50).
- **Failure Mode:** System erroneously counts all credits as `Salary` or general income, leading to an artificially bloated income and unrealistic savings rate (e.g. 85%).
- **Handling Strategy:**
  - `Salary` category must require strong positive signals (e.g., narration contains `SALARY`, `PAYROLL`, `WAGES`, or monthly recurring credit > ₹15,000 from a corporate entity).
  - Small credits (< ₹500) labeled as `Other` or `Interest/Cashback`.
  - P2P credits labeled as `Other` (income type: transfer/reimbursement).

### 4.3 Internal Transfers & Credit Card Bill Autopay
- **Scenario:**
  - Transfer between user's own accounts (`SELF TRANSFER`, `NEFT TO OWN A/C`, `TRANSFER TO FD`).
  - Credit card payments (`CRED`, `BILLDESK`, `HDFC CC AUTODEBIT`, `SBI CARD`).
- **Failure Mode:** Double counting: User spends ₹50,000 on credit card, then pays ₹50,000 CC bill from bank account. If both are counted, spend is recorded as ₹100,000.
- **Handling Strategy:**
  - Rule engine pattern matching: tag `CRED`, `BILLDESK *CREDIT CARD`, `CC AUTOPAY` as category `Bills` with `metadata.is_debt_payment = True`.
  - Flag self-transfers (`SELF`, `OWN ACC`) with `metadata.is_self_transfer = True` and provide a toggle in the UI: *"Include/Exclude self transfers in spend"*.

### 4.4 LLM Rate Limiting, Timeouts & Schema Violations (Groq)
- **Scenario:**
  - Batch of 50 transactions sent to Groq API returns HTTP 429 (Rate Limit Exceeded) or HTTP 504 (Timeout).
  - LLM hallucinates categories not in the 10-item taxonomy (e.g. `Healthcare`, `Pets`, `Charity`).
  - LLM returns malformed JSON or markdown codeblocks wrapping JSON.
- **Handling Strategy:**
  - Strict Pydantic parsing on LLM JSON output.
  - If category is outside taxonomy enum, automatically coerce to `Other`.
  - Fallback ladder:
    1. Try Groq batch with 5s timeout.
    2. On 429/timeout: retry once with exponential backoff (1s).
    3. If still failing: seamlessly degrade to Rule-Engine & Dictionary results; tag unclassified items as `Other` (confidence: 0.0). The user pipeline **never** crashes due to LLM failure.

## 5. Recurring Payment Detection Edge Cases (Pipeline Stage 4)

### 5.1 Amount Variations in Recurring Bills
- **Scenario:**
  - Utility bills (Electricity ₹1,450 in May, ₹2,100 in June; Water bill ₹320 vs ₹450).
  - Usage-based subscriptions (AWS cloud bill ₹850 vs ₹1,200).
- **Failure Mode:** Exact amount matching fails to detect the utility as recurring.
- **Handling Strategy:**
  - Two-mode recurring detector:
    - *Fixed amount subscriptions* (Netflix, Rent, SIP): Amount tolerance within ±5% or ±₹50.
    - *Variable bills* (Electricity, Broadband, Gas): Merchant match with interval tolerance (~28–32 days) even if amount varies up to ±40%, categorized under `Bills`.

### 5.2 Calendar Drift & Weekend / Bank Holiday Offsets
- **Scenario:**
  - A loan EMI due on the 5th of every month:
    - April 5 is Saturday -> debited April 7 (Monday) -> interval: 33 days.
    - February has only 28 days -> interval: 28 days.
- **Failure Mode:** Strict 30-day interval requirement misses monthly payments.
- **Handling Strategy:**
  - Interval window for monthly frequency configured as **26 to 35 days**.
  - Check day-of-month consistency (e.g., transaction date is consistently between 4th and 8th of the month).

### 5.3 Short Statement Timeframes (1 Month or Less)
- **Scenario:** User uploads a statement covering only 15 to 30 days.
- **Failure Mode:** An algorithm requiring ≥ 2 occurrences will detect **zero** recurring payments, giving the false impression that the user has no subscriptions or EMIs.
- **Handling Strategy:**
  - Detection fallback for statements with span < 45 days:
    - Pattern-based identification: If merchant matches known subscription providers (`NETFLIX`, `SPOTIFY`, `HOTSTAR`) or narration contains `EMI` / `SIP`, identify as a *"Probable Recurring Subscription"* with confidence 0.70.
    - Display UI advisory badge: *"Statement covers < 45 days. Showing estimated subscriptions based on known merchants."*

### 5.4 False Positive Recurring Payments
- **Scenario:**
  - Daily or frequent regular spends: User orders food on Swiggy for ₹249 five times in a week.
  - Two identical one-off purchases: User buys two items for ₹499 on Amazon 10 days apart.
- **Failure Mode:** Daily food orders or random identical purchases flagged as a "monthly subscription".
- **Handling Strategy:**
  - Enforce minimum interval criteria: Monthly recurring payments must have intervals ≥ 25 days.
  - High-frequency daily spends (< 5 days interval) explicitly disqualified from recurring subscription status.
  - Require minimum 2 consecutive cycles with cadence alignment.

## 6. Financial Metrics & Aggregation Edge Cases (Pipeline Stage 5)

### 6.1 Negative Net Savings & Negative Savings Rate
- **Scenario:** User spent ₹1,20,000 while total income was ₹80,000 (spent from previous savings or overdraft).
  - `Savings = 80,000 - 1,20,000 = -40,000`
  - `Savings Rate = (-40,000 / 80,000) * 100 = -50%`
- **Failure Mode:** UI breaks or displays non-sensical progress bars; division or rendering errors.
- **Handling Strategy:**
  - Support negative numbers in `MetricCard` with red/alert styling and minus sign: `-₹40,000 (-50.0%)`.
  - Cap savings rate progress bar visually at 0% minimum with an overspend warning indicator.

### 6.2 Zero Income Statement (Expense-Only Account)
- **Scenario:** User uploads statement for a dedicated spending credit card or secondary UPI account where salary is never credited (`Income = 0`).
- **Failure Mode:** `ZeroDivisionError: division by zero` when computing `(Savings / Income) * 100`.
- **Handling Strategy:**
  - Explicit check in `backend/app/pipeline/metrics.py`:
    ```python
    savings_rate = 0.0 if total_income == 0 else round(((total_income - total_spend) / total_income) * 100, 1)
    ```
  - Display UI label: *"N/A (Expense-only statement)"* when `total_income == 0`.

### 6.3 Single Outlier Transactions Distorting Aggregations
- **Scenario:** User made a one-off ₹5,00,000 payment (e.g. car purchase, tax payment, or property deposit) alongside typical ₹200–₹500 daily transactions.
- **Failure Mode:** Donut charts compress all daily living categories into invisible slivers (< 1%); monthly spend charts scale off-screen.
- **Handling Strategy:**
  - Flag single transactions exceeding 50% of total spend as `is_outlier = True`.
  - Dashboard supports a toggle: *"Exclude major one-off transactions (> ₹1,00,000)"*.

### 6.4 Cross-Year Statement Spans
- **Scenario:** Statement spans from November 2024 to February 2025.
- **Failure Mode:** Grouping by month name (`"November"`, `"December"`, `"January"`) sorts alphabetically or chronologically out-of-order (`January 2025` placed before `November 2024`).
- **Handling Strategy:**
  - Group monthly data by ISO period string `YYYY-MM` (e.g. `2024-11`, `2024-12`, `2025-01`).
  - Format for UI display as `Nov 2024`, `Dec 2024`, `Jan 2025` preserving chronological sort order.

## 7. Insight Generation Edge Cases (Pipeline Stage 6)

### 7.1 Sparse or Minimal Data (< 3 Transactions)
- **Scenario:** Uploaded file contains only 1 or 2 transactions.
- **Failure Mode:** System fails requirement *"Must generate ≥ 3 personalized financial insights"* or crashes with index errors trying to fetch top 3 categories.
- **Handling Strategy:**
  - Dynamic template fallback logic in `backend/app/pipeline/insights.py`:
    - Insight 1: Total volume and date range (`"You recorded {count} transaction(s) between {date_start} and {date_end}."`).
    - Insight 2: Spend breakdown (`"Your largest transaction was ₹{amount} for {merchant}."`).
    - Insight 3: Upload guidance (`"Upload a 3 to 6-month statement to unlock deep spending patterns, subscriptions, and savings rate trends."`).

### 7.2 Dominance of "Other" Category
- **Scenario:** Obscure bank narration rules cause 70%+ of transactions to fall into `Other`.
- **Failure Mode:** Insight generated says: *"You spent ₹45,00,00 on Other — your largest category!"*, which is unhelpful and damages credibility.
- **Handling Strategy:**
  - When generating Top Category insights, find the highest spending category **excluding** `Other`.
  - Add a dedicated review prompt insight: *"₹{amount} (X%) is currently in 'Other'. Review and re-categorize in the transaction table below to improve analysis accuracy."*

### 7.3 Hallucination & Advice Prohibition in LLM Insights
- **Scenario:** External LLM gives illegal or harmful financial advice (e.g. *"You should invest ₹50,000 in crypto"* or hallucinates numbers not present in the data).
- **Handling Strategy:**
  - System prompt constraint for Groq LLM:
    - *"You are a personal finance data summarizer, NOT a financial advisor. Never give direct investment recommendations. Only state factual observations citing exact computed amounts from the provided metrics."*
  - Guardrail validator: Verify every currency figure cited in the generated insight string exists in the input metrics schema; reject and use Tier 1 template if discrepancy detected.

## 8. Frontend & User Experience Edge Cases (Pipeline Stage 7)

### 8.1 Category Override Propagation
- **Scenario:** User manually overrides a transaction category in the table (e.g. changes `SWIGGY` from `Food` to `Shopping`).
- **Failure Mode:** UI updates the table row, but Summary Cards, Top Categories donut chart, and Insight text remain stale unless a full page refresh occurs.
- **Handling Strategy:**
  - React Query invalidation: On successful `PATCH /sessions/{id}/transactions/{txn_id}`, trigger invalidation for `['analytics', sessionId]` and `['insights', sessionId]`.
  - Optimistic UI update for the table row with rollback on error.

### 8.2 Extremely Long Merchant Narrations & Large Number Formatting
- **Scenario:**
  - Narration: `UPI/DR/123456789012/VERY_LONG_NAME_OF_A_LOCAL_ENTERPRISE_AND_TRADING_CO/SBI/PAYMENT` (80+ characters).
  - Amount: `₹12,45,67,890.00` (crores).
- **Failure Mode:** Table column blowout, horizontal scrolling overflow, broken mobile flex containers.
- **Handling Strategy:**
  - Table cells use `max-w-xs truncate` with tooltip displaying full `description_raw` on hover.
  - Number formatter handles large values with abbreviation for compact cards (e.g. `₹1.25L` or `₹12.45Cr` with full amount in tooltip).

### 8.3 Browser Print & PDF Export Layout Breaks
- **Scenario:** User triggers "Download PDF / Print Report".
- **Failure Mode:** Page breaks split a table row in half across two pages; dark mode background causes black ink waste; charts fail to render if printing before canvas loads.
- **Handling Strategy:**
  - CSS `@media print` rules:
    - Force light theme colors (`background: white; color: black`).
    - Set `page-break-inside: avoid` on metric cards, chart containers, and table rows.
    - Hide interactive UI elements (`FileUpload`, category dropdowns, filter controls, pagination buttons).

### 8.4 Session Expiration During Active User Browsing
- **Scenario:** User leaves the dashboard tab open; 48-hour session TTL expires on backend. User then clicks "Override Category" or "Export Report".
- **Failure Mode:** Unhandled 404 or 500 error causes white-screen crash.
- **Handling Strategy:**
  - Global API interceptor catches 404 on session endpoints.
  - Renders a clean session expired modal: *"Your anonymous session has expired and statement data was purged for your privacy. Please upload your statement again."*

## 9. Security, Privacy & Lifecycle Edge Cases

### 9.1 Accidental PII Leakage in LLM Prompts
- **Scenario:** Raw description contains sensitive personal data:
  - Account numbers: `TRANSFER A/C 50100012345678`
  - Phone numbers / Aadhaar hints / Employee IDs: `SALARY EMP 9876543210 JOHN DOE`
- **Handling Strategy:**
  - Sanitization filter before sending payload to Groq:
    - Mask 10-digit phone numbers: `\b[6-9]\d{9}\b` -> `[PHONE]`
    - Mask account/card numbers (8+ digits): `\b\d{8,18}\b` -> `[ACC]`
    - Strip full names from standard P2P strings: `UPI/CR/12345/FIRSTNAME LASTNAME/...` -> clean merchant or `UPI Transfer`.

### 9.2 Malicious File Uploads & CSV Injection
- **Scenario:**
  - Attacker uploads a CSV containing formula injection payloads: `=cmd|'/C calc'!A0` or `=HYPERLINK("http://malicious.site")` in the narration column.
  - Upload of `.exe`, `.sh`, or zip bombs disguised with `.csv` extension.
- **Handling Strategy:**
  - Content-type validation and header sniffing in FastAPI upload route.
  - Sanitize all string fields when exporting reports or rendering in HTML: prefix formula triggers (`=`, `+`, `-`, `@`) with a single quote `'`.

### 9.3 Double-Submission & Race Conditions
- **Scenario:** User double-clicks "Analyze Statement" or drops multiple files simultaneously.
- **Handling Strategy:**
  - Frontend disables upload button immediately on first submit with visual loading state.
  - Backend creates unique session UUID per request and handles file processing idempotently.
